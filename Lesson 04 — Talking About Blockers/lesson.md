# Lesson 04 — Talking About Blockers

## 1. Lesson Overview

**Target Level:** Level 1  
**Target WPM:** 115–130 WPM  
**Meeting Type:** Daily Stand-up  
**IT Context:** Web Development / QA / API Dependency  
**Characters:** 2  
**Conversation Length:** 12–16 turns

### Main Goal

By the end of this lesson, you should be able to:

- Recognize when someone asks about blockers.
- Explain a simple blocker.
- Explain what you are waiting for.
- Explain how a blocker affects your work.
- Say whether a blocker is currently blocking your progress.
- Ask for help when necessary.

### Core Skill

> **Identify the blocker → Explain the impact → Explain what you need**

---

# 2. Situation

It is Wednesday morning.

Sarah, the Project Manager, is checking David's progress during the daily stand-up.

David is working on a new product API integration.

Most of his development work is complete, but he cannot finish testing because he is waiting for the API credentials from the client.

Sarah wants to understand:

- What is blocking David?
- How is it affecting the task?
- What does David need?

---

# 3. IT Context

The team is integrating a new payment API into an e-commerce website.

David has completed most of the implementation.

However, he needs the API credentials before he can test the integration.

Current status:

- API integration: mostly implemented
- Development: almost complete
- Testing: waiting
- Blocker: API credentials
- Dependency: client

## Asking about blockers

### “Any blockers?”

= Có blocker nào không?

---

### “Are you blocked on anything?”

= Bạn có đang bị vướng ở việc gì không?

---

### “Is anything blocking you?”

= Có gì đang cản trở bạn không?

---

## Explaining a blocker

### “I'm waiting for...”

> “I'm waiting for the API credentials.”

= Tôi đang chờ API credentials.

---

### “I can't move forward until...”

> “I can't move forward until I get access.”

= Tôi không thể tiếp tục cho đến khi có quyền truy cập.

---

### “I'm blocked by...”

> “I'm blocked by the missing API credentials.”

= Tôi đang bị vướng vì thiếu API credentials.

---

# 6. Explaining the Impact

It is useful to explain not only **what** the blocker is, but also **what it affects**.

### “It’s blocking testing.”

= Nó đang cản trở việc testing.

### “It’s delaying the task.”

= Nó đang làm chậm task.

### “I can't test it yet.”

= Tôi chưa thể test nó.

### “I can continue with the development, but I can't test it yet.”

= Tôi vẫn có thể tiếp tục development, nhưng chưa thể test.

---

# 7. Natural Meeting English

A developer does not always need to say:

> “I currently have a blocker that is preventing me from continuing my work.”

A natural meeting response is:

> “I'm waiting for the API credentials, so I can't test it yet.”

Shorter.

Clearer.

More useful.

---

Another common pattern:

> “I'm good on development, but I'm blocked on testing.”

This quickly communicates:

**Development → okay**

**Testing → blocked**

---

# 8. Natural / Reduced Speech

Pay attention to these chunks.

### “I'm waiting for...”

Recognize:

> **waiting for**

as one sound group.

---

### “I can't test it yet.”

The important information is:

> **can't test**

and:

> **yet**

**yet** tells you the testing has not happened up to now.

---

### “Are you blocked on anything?”

Do not try to translate **blocked** literally.

In a development meeting:

> **blocked = unable to make progress because something is preventing you**

# 9. Conversation

### Sarah — Project Manager

Morning, David. How's the payment API integration going?

### David — Developer

Pretty good. The implementation is almost done.

### Sarah

Nice. Anything blocking you?

### David

Yeah, I'm waiting for the API credentials from the client.

### Sarah

Okay. Does that block the development?

### David

Not really. I can finish the code, but I can't test the API yet.

### Sarah

Got it. When do you expect to get the credentials?

### David

I'm not sure. I asked the client yesterday, but I haven't heard back yet.

### Sarah

Okay. Is there anything else you can work on?

### David

Yeah, I can finish the error handling while we wait.

### Sarah

Sounds good. I'll follow up with the client.

### David

Thanks. That would help.

### Sarah

No problem. Keep me posted if anything changes.

### David

Sure, will do.

# 14. Speaking Pattern — Explaining a Blocker

Use this structure:

### 1. State the blocker

> “I'm waiting for ___.”

### 2. Explain the impact

> “I can't ___ yet.”

### 3. Explain what you can still do

> “I can still ___.”

### 4. Ask for help if needed

> “Could you check with ___?”

---

## Example

> I'm waiting for the API credentials.  
> I can't test the integration yet.  
> I can still finish the error handling.  
> Could you check with the client?
