# Lesson 05 — Understanding Requirements

## 1. Lesson Overview

**Target Level:** Level 1  
**Target WPM:** 120–135 WPM  
**Meeting Type:** Requirement Discussion  
**IT Context:** E-commerce / Feature Requirement / User Flow  
**Characters:** 2  
**Conversation Length:** 14–18 turns

### Main Goal

By the end of this lesson, you should be able to:

- Understand a simple feature requirement discussed in a meeting.
- Identify what the user should be able to do.
- Identify what the system should do.
- Recognize basic business rules.
- Distinguish between the current behavior and the new behavior.
- Summarize a simple requirement in your own words.

### Core Skill

> **Who → What → When → System behavior**

The goal is to understand the requirement as a **behavior**, not as a collection of individual English words.

---

# 2. Situation

Sarah, the Project Manager, is discussing a new requirement with David.

The client wants to change how the product page handles out-of-stock products.

David needs to understand exactly what should happen when a product is unavailable.

---

# 3. IT Context

The team is working on an e-commerce website.

The client wants:

- Out-of-stock products to remain visible.
- Customers to see an “Out of Stock” message.
- The Add to Cart button to be disabled.
- Customers to be able to sign up for a notification.

The requirement sounds simple, but several system behaviors need to be understood correctly.

---

# 4. Requirement Breakdown

Before listening to the conversation, understand the basic logic.

### Current situation

A product is out of stock.

### New requirement

The product should:

1. Stay visible.
2. Show an “Out of Stock” message.
3. Disable Add to Cart.
4. Allow the customer to sign up for a notification.

Think in terms of:

> **When X happens → the system should do Y.**

# 6. Business Meeting Patterns

## Describing a requirement

### “We want users to...”

> “We want users to see the product even when it's out of stock.”

= Chúng tôi muốn user vẫn nhìn thấy sản phẩm ngay cả khi hết hàng.

---

### “The system should...”

> “The system should disable the Add to Cart button.”

= Hệ thống nên vô hiệu hóa nút Add to Cart.

---

### “When the product is out of stock...”

> “When the product is out of stock, the button should be disabled.”

= Khi sản phẩm hết hàng, button phải được disable.

---

### “Users should be able to...”

> “Users should be able to sign up for a notification.”

= User phải có thể đăng ký nhận thông báo.

---

# 7. Current vs New Behavior

This distinction is important in requirements meetings.

### Current behavior

> “Right now, the product disappears when it's out of stock.”

Meaning:

> Hiện tại sản phẩm bị ẩn khi hết hàng.

### New behavior

> “We want to keep it visible.”

Meaning:

> Requirement mới là vẫn hiển thị sản phẩm.

When listening to requirements, always ask yourself:

> **What happens now?**

and:

> **What should happen after the change?**

---

# 8. Natural Meeting English

People often use short phrases when discussing requirements.

### “Right now...”

This usually introduces the **current behavior**.

### “We want to...”

This usually introduces the **requested behavior**.

### “It should...”

This usually introduces the **expected system behavior**.

### “Users should be able to...”

This usually introduces a **user action**.

These patterns are more important than memorizing isolated grammar rules.

---

# 9. Natural / Reduced Speech

Listen for these chunks.

### “We want to keep it visible.”

Focus on:

> **want to keep**

---

### “Users should be able to sign up...”

Focus on:

> **should be able to**

This pattern is very common when discussing requirements.

---

### “When it's out of stock...”

Focus on:

> **out of stock**

Treat it as one meaning unit.

You do not need to process each word separately.

# 15. Speaking Pattern — Explaining a Requirement

When you understand a requirement, summarize it using:

### Current behavior

> “Right now, ___.”

### New behavior

> “The new requirement is to ___.”

### System behavior

> “So, the system should ___.”

### User behavior

> “Users should be able to ___.”

---

## Example

> Right now, out-of-stock products disappear.  
> The new requirement is to keep them visible.  
> The Add to Cart button should be disabled.  
> Users should be able to sign up for a notification.

---

# 16. Speaking Practice

Imagine Sarah explains this requirement:

> Customers can cancel an order within 30 minutes.

You need to explain your understanding.

Try to say:

> “So, if I understand correctly...”

Then explain:

- Who can cancel.
- What they can cancel.
- How long they have.

# 17. Response Practice

### Requirement

> “We want users to see the product even when it's out of stock.”

Possible response:

> “Got it.”

Better:

> “Okay, so the product should stay visible even when it's out of stock.”

---

### Requirement

> “The Add to Cart button should be disabled.”

Possible confirmation:

> “So users can't purchase it while it's out of stock, right?”

---

### Requirement

> “Users should be able to sign up for a notification.”

Possible confirmation:

> “Okay, so they can get notified when it's available again?”
